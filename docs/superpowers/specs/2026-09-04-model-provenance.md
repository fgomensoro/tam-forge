# Immutable model provenance (#53)

User authorized one additional complete ticket after #54, with autonomous routine choices and merges. This implements provenance persistence only. No model execution, scoring publication, new rubric weights, recording/audio/auth/recovery/native UI changes, or production operations. #54 is closed via PR149 and is the actual prerequisite. Existing worktree is reused from main022fcdb.

## Persistence requirements

1. **Content registries.** Add append-only `prompt_versions` and `output_schema_versions`, positive integer identity, owner scope, stable key/version uniqueness, bounded canonical content, SHA256 bytes, hash-format version and creation timestamp. Prompt content identity is exact UTF-8 bytes (no whitespace/newline normalization). Schema identity is versioned deterministic canonical JSON, with finite JSON numbers, sorted object keys, preserved array order and no lossy Unicode normalization. Require same key/version plus same bytes to return the existing record; changed bytes conflict. Lookups by owner+hash must resolve verified content. Store/register #54 snapshots under their exact URNs/version discriminators; no arbitrary schema fallback or prompt generation is needed.
2. **Reuse rubric definitions.** Resolve an existing owner/config/rubric row and its ordered dimensions. Prefer a small append-only one-to-one `rubric_version_hashes` binding to the existing rubric/config IDs, config SHA256 and a canonical extracted rubric SHA256. This is an address/index over an existing definition, not a parallel rubric registry: no separately supplied definition, weights or scale, and no new RubricVersion class. Verify the extracted canonical release entry matches all persisted rubric/dimension fields before binding; reject missing/mismatched releases. This avoids rewriting immutable historical rows or changing their source hash. A migration may create bindings for validated legacy rows, or the registry may append them lazily; either way every run requires the binding before insertion.
3. **Immutable provenance graph.** Add `model_runs`, `model_run_context_items`, `model_run_events` and `agent_tool_calls`, each append-only and hash-addressed. A run is one actual invocation identity with a frozen header; queue/lease/retry scheduling remain in BackgroundJob. Header captures owner, activity, committed attempt+hash, prompt version+hash, existing config/rubric binding, output-schema version+hash, requested model, declared SDK/CLI versions and canonical ordered context-manifest hash. Optional job/predecessor-run IDs link execution attempts without mutating the earlier invocation. Every retry invocation is a distinct run; same idempotency key and identical payload returns the original, changed payload conflicts. Include a durable invocation key in the hash envelope so identical requests at different times do not collapse.
4. **Exact context, no orphan references.** Context items have ordinal, reason code, typed source reference, source version/hash and hash of the exact prepared input content when a projection is used. Freeze a bounded ordered manifest atomically with the header; reject duplicate ordinals/items, empty required evidence, changed order/hash, cross-owner/activity/attempt sources, missing IDs and mismatched hashes. Consume #54 attempt-text/artifact-text/time locator shape without replacing evidence with URLs or copied history. The persistence layer verifies existence, owner, source hash/version and activity-artifact link. Attempt text resolves against the committed envelope; schema syntax alone is not sufficient. Unproved artifact subtype/locator semantics must fail closed. Do not store raw audio, audio URLs, OAuth credentials, arbitrary file paths or full context transcripts in run/tool audit JSON. Later analysis publication still owns material-claim support and eligibility checks.
5. **Append events, never update run records.** A typed lifecycle repository accepts expected latest sequence/state and appends immutable events atomically under a run lock/unique sequence constraint. Events record running and terminal outcome, exact resolved model and SDK/CLI versions when observed, timing, invocation/attempt identity and bounded typed failure category. Preserve every failure, cancellation and retry disposition. Queued/start/completion are events over the frozen header; completion cannot overwrite provenance. Do not manufacture resolved model IDs before execution reports them. Success requires a resolution event; retry scheduling can reference existing job APIs later. Terminal outcome/output hashes may be captured without creating analysis/observation/publication records. No service in this ticket invokes a model or consumes a live job.
6. **Tool audit.** Persist immutable request/result events (or separate finalized call records with an explicit request event) so pending calls are not silently lost. Use run+call identity+sequence uniqueness, exact tool name/version/schema hash, typed bounded redacted argument/result metadata, exact evidence references, outcome/error category and timing. Content hashes explicitly identify the persisted redacted audit envelope; never claim they reproduce omitted raw tool content. No tool execution/dispatch is implemented. Reject credentials, URLs and unrestricted learner-text blobs by an allowlisted audit contract rather than a generic JSON scrubber.
7. **Database enforcement.** ORM and PostgreSQL prevent UPDATE/DELETE/TRUNCATE on all new immutable records/bindings. Composite FKs enforce owner and activity provenance; INSERT guards verify pinned hashes and reject later context additions after the manifest has been sealed. Uniqueness/transaction locks make duplicate publication and expected-state appends safe under concurrency. Define a versioned hash envelope excluding generated row IDs/timestamps unless they intentionally form invocation identity; validate stored digest against canonical bytes and references, including direct SQL insertion. Do not merely check digest length. Downgrade removes only this revision's objects.


## Locked implementation rulings

- Reuse existing rubric/config rows with an append-only hash binding; never modify historical content or fabricate missing English/TAM scoring rubrics.
- Initial context profile is **committed-attempt-text-v1** only. Its exact source is immutable Attempt.original_text, the committed JSON envelope, selected via #54 AttemptTextReference and matching commitment hash. No arbitrary external artifact fetching, transcription subtype assertion or caller-supplied trust flag. Artifact-backed input remains explicitly unsupported until a trusted resolver can prove actual object content. This narrows the earlier assessment's optional written-artifact idea to a completely verifiable DB boundary; wrong choice costs a later resolver extension, not fabricated evidence.
- References select only learner-authored string fields: reading key_ideas entries, boundary_or_failure, tam_customer_example, unresolved_question; SQL query/result/validation/explanation/business_meaning; case discovery_questions/assumptions/working_notes/final_artifact/decisions/risks/unresolved_questions; writing draft_markdown/self_edit_notes; pipeline completed_action/artifact_summary/next_action. Reject prompt/audience, canonical prompt/facts, requested action/facts/tone and any other task/context metadata. Array indices must resolve exactly, ranges must fit decoded strings. No normalization; Unicode code-point exclusive end. Persist locators and prepared-input hashes, not copied text.
- New model invocation headers are immutable. Lifecycle and tool request/result events append; existing BackgroundJob remains scheduling authority. No new queue. Requested versions may be recorded at registration; resolved model/SDK/CLI identities must come from observed running events and never placeholders.
- Hash formats must be explicitly versioned and reproducible from stored bytes. Every persisted record and reference pins content hashes; direct SQL inserts cannot forge a digest or a source association. Keep canonical serialization and SQL verification simple and consistent, and state exact byte domains in the runbook. No generic cryptographic framework.
- Prompt/schema payloads max1MiB UTF8, context items1..64 with manifest max256KiB, tool audit envelopes max16KiB with only typed identifiers/version/hash/count/state/error fields; model/event envelopes max256KiB. Integer IDs exclude booleans/strings. Safe keys/version strings max128; hashSHA25632bytes. Context ordinals contiguous0-based, exact sequence/order and duplicate rejection. Model run unique owner+invocation_key, same full original request replays, changed input conflicts. Lifecycle expected sequence and state enforced atomically: registered->running->succeeded|failed|cancelled; cancellation/failure from registered allowed. Terminal events cannot be followed. Tool request must precede one terminal result; preserve errors and cancellation.
- Sealing can be enforced with deferred consistency checks at transaction commit: the run header's immutable ordered manifest must equal its complete context rows; subsequent additions cannot change the committed manifest. No mutable sealed flag required. Keep positive and negative integration cases in the same real PostgreSQL suite.
